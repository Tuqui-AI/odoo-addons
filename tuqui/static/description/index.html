Tuqui — Companion module for Odoo

Connect your Odoo to Tuqui in one click.

OAuth 2.0 client credentials

Replaces per-user API keys with a single workspace-level client_id / client_secret pair that can be rotated or revoked at any time. After installation, an admin (base.group_system) can activate Tuqui from the Tuqui menu and the workspace becomes reachable from claude.ai, ChatGPT, or any MCP-compatible client.

Generic RPC gateway with local policy engine

A single /tuqui/rpc endpoint exposes Odoo's ORM via execute_kw-style calls. Permission is decided by a local policy engine, never by a hardcoded allowlist — so new Tuqui capabilities don't require shipping a new module version to clients.

  • Default mode: hardcoded behaviour, no rules consulted. Private methods always blocked; absolute blocks (sudo, with_user/env/company, flush*/invalidate*, Python dunders) apply universally. Reads/writes/executes go through the acting user's Odoo ACL.
  • Advanced mode: allow / deny rules with fnmatch globs. Deny wins. For private methods, an exact allow rule is required (wildcards rejected at save).
  • Read-only preset: one-click button that adds the deny rules needed to lock the connection down to reads only.

Access log

Every call is recorded in tuqui.access.log with separate policy and runtime axes — making audit queries unambiguous about whether a call was blocked by policy, denied by Odoo's ACL, or failed at runtime. Capped by row count so the table stays bounded without coupling to a time-based retention.
